# ChargeHub · 东软电动汽车充电桩应用管理平台

这是充电桩管理系统。运行起来会看到三类界面：

| 窗口 | 是什么 | 谁开 |
|------|--------|------|
| **管理端** | 服务器 + 运营后台（写数据库、听 8888 端口） | 全组联调时 **只允许一台电脑开** |
| **用户端** | 手机竖屏充电 App（底栏找桩 / 预约 / 充电 / 订单 / 我的） | 每个人的虚拟机都可以开，可以同时开很多个 |
| **运营大屏** | 浏览器里的图表 | 任何人用浏览器打开即可（只看、不改数据） |

只在 **Ubuntu 22.04 桌面** 里运行。不要在 Windows 里双击这些程序。

## 0. 三件不要忘

1. **先开管理端，再开用户端。** 管理端关了，用户端一定连不上。
2. 演示号 **不要点「注销」**：`13800138000` / `123456`。测注销请自己再注册一个号。
3. 用户端「服务器地址」：
   - 管理端也在 **你这台** 电脑 → 填 `127.0.0.1:8888`
   - 管理端在 **组里另一台** 电脑 → 填那台管理端窗口 **最底下** 显示的 `IP:8888`

## 1. 第一次准备（每人做一次）

1. 安装 Ubuntu 22.04（虚拟机即可）。
2. 把整个 `ChargeHub` 文件夹放进 Ubuntu（U 盘，或虚拟机共享文件夹，名字叫 `ChargeHub`）。
3. 打开「终端」，复制执行：

```bash
sudo apt update
sudo apt install -y build-essential qtbase5-dev qt5-qmake libqt5sql5-sqlite python3-flask python3-tk xdg-utils
```

4. 再编译一次（会弹出窗口）：

```bash
# 共享文件夹名叫 ChargeHub 时：
bash /mnt/hgfs/ChargeHub/scripts/rebuild.sh

# 文件夹是拷进 Ubuntu 的：
cd 你的ChargeHub目录
bash scripts/rebuild.sh
```

成品在主目录 `ChargeHub-Linux`。共享盘找不到时：

```bash
sudo mkdir -p /mnt/hgfs
sudo vmhgfs-fuse .host:/ /mnt/hgfs -o allow_other
```

## 2. 个人自己测（日常开发用这个）

一个人改代码、验功能、交作业前自查，都走这一节。  
**整套程序都在你这一台 Ubuntu 虚拟机里**，不连组员电脑，也不用改桥接、不用填局域网 IP。

和联调的差别（先记这一句）：

| | 个人自测（本节） | 全组联调（第 4 节） |
|--|------------------|---------------------|
| 开管理端 | 你自己开 | 全组只开一份（值班那台） |
| 用户端「服务器地址」 | **原样** `127.0.0.1:8888` | 填值班机器底栏的 `IP:8888` |
| 数据在哪 | 只在你这台虚拟机的库里 | 只在值班服务器的库里 |

自己测时开自己的管理端完全没问题。测完若要参加联调，**先关掉**自己的管理端，再按第 4 节连组里服务器。

### 2.1 打开管理端和用户端

第一次先编一次（改代码后再编一次）：

```bash
bash scripts/rebuild.sh
```

之后只双击这两个文件：

| 文件 | 打开什么 | 登录 |
|------|----------|------|
| `ChargeHub/scripts/打开运营后台.bat` | 管理端 | `admin` / `123456` |
| `ChargeHub/scripts/打开用户端.bat` | 用户端 | `13800138000` / `123456`，服务器 `127.0.0.1:8888` |

用户端先点「连接」，连上后用顶栏切换 **登录** / **注册**。登录用演示号即可；注册须满足密码规则（6～20 位且含大小写字母和数字），成功后写入管理端数据库并自动登录。窗口是手机竖屏，底栏切换找桩 / 预约 / 充电 / 订单 / 我的。  
大屏：管理端里 **运营决策大屏** → **打开 Web 大屏**。

### 2.2 建议自测顺序（约 10 分钟）

下面都在 **你自己的** 用户端 + 管理端上做。演示号不要点「注销」。

1. **登录 / 注册**  
   用户端能进首页；管理端「用户管理」里能看到 `13800138000`。点「注册」页用新手机号注册（密码须含大小写字母和数字），管理端应出现该用户。
2. **找桩**  
   登录后会弹出位置授权。同意后优先用 Windows 定位（Wi-Fi/系统定位）。不准时会弹出地图：**拖动**查看周围，**点击**标定位置；也可随时点「地图选点」或填精确住址。点电站「位置 / 导航」可拖动预览图，并从该点导航到充电站。
3. **预约 / 充电**  
   选一根闲置桩：预约或直接开始充电。用户端充电页应有度数、金额在变；总价含固定 1 元起步价。
4. **停止并结算**  
   结束充电 → 待结算 → 结算。余额应减少；管理端「订单跟踪」应出现这条订单。
5. **充值**  
   个人中心模拟充值，余额增加；管理端能对上。
6. **大屏**  
   浏览器 `http://127.0.0.1:5000`，营收/订单数应跟着刚才的结算变（刷新即可）。
7. **管理端操作**  
   试：冻结某个 **自己新注册的号**（不要冻演示号）、加电站或改电价、选中电站点「启用分时电价」、把闲置桩标故障再「远程重启 / 恢复」、在「订单跟踪」对卡住的单点强制结束 / 代结算、智能分析里「采纳选中调度建议」、打开「操作审计」。用户端用被冻号应无法登录。充电中把用户端关掉，约 60 秒后该桩应回到闲置，订单变待结算。充电中度数/金额除轮询外，服务端大约每 5 秒还会推一次 `PUSH_CHARGE`。
8. **注销（用新号）**  
   再注册一个手机号，用该号测「注销账号」。注销后不能再登录、不能再用同一手机号注册。**不要用 13800138000 测这一条。**

测崩了、窗口关了：从 2.1 再开一遍即可。库在 `~/ChargeHub-Linux/admin/data/chargehub.db`，一般不用手删。

### 2.3 改了代码怎么再测

1. 源码改完并保存（Windows 里改的话，确认虚拟机共享盘已是最新文件）。
2. Ubuntu 终端只跑：

```bash
bash /mnt/hgfs/ChargeHub/scripts/rebuild.sh
```

（工程是拷进来的则：`cd 工程目录 && bash scripts/rebuild.sh`）

3. 等两个窗口重新弹出，再走 2.1 登录、2.2 里你改过的那几条。
4. 不要在共享盘上直接敲 `make`。只保存文件、不跑 `rebuild.sh`，虚拟机里的程序还是旧的。

只想重新弹出窗口、没改代码：用 `scripts/start.sh`，或按 2.1 再双击 `run.sh`。

### 2.4 个人自测时不要做的事

- 用户端服务器地址不要填组员的 IP（那是联调用法）。
- 不要同时再开第二份管理端（本机会提示已在运行或 8888 占用）。
- 不要把个人库和联调服务器混为一谈：你这边充的电，组员电脑上看不到，这是正常的。
- 测完要参加第 4 节联调：关掉自己的管理端和用户端，用户端改连值班服务器。

## 3. 计算机网络基础（联调必读）

把电脑想成一栋楼，程序想成房间里的人。

### IP 地址 = 这栋楼的门牌号

每台连上网的电脑都有一个 IP，例如 `192.168.1.8`。  
组员要找到「开着管理端的那台电脑」，靠的就是这个门牌号。

常见两种：

| 你看到的地址 | 白话 | 什么时候用 |
|--------------|------|------------|
| `127.0.0.1` | 「我自己这台电脑」 | 用户端和管理端在 **同一台** Ubuntu 里 |
| `192.168.x.x` 或 `10.x.x.x` | 「局域网里别人也能敲的门牌」 | 用户端在 **另一台** 电脑 / 另一台虚拟机 |

**千万不要** 在别人的用户端里填 `127.0.0.1`：那会连到 **他自己** 的电脑，连不到你。

### 端口 = 这栋楼里的房间号

同一台电脑可以同时跑很多程序，靠端口区分：

| 端口 | 程序 | 谁来敲门 |
|------|------|----------|
| **8888** | 管理端（ChargeHub 服务器） | **用户端程序**（不要用浏览器打开） |
| **5000** | 运营大屏 Flask | **浏览器** 输入 `http://IP:5000` |

所以：

- 用户端登录页填：`192.168.1.8:8888`（程序之间说话）
- 浏览器大屏填：`http://192.168.1.8:5000`（网页）

两套地址不要混。

### 「同一局域网」= 连的是同一张网

要让 A 电脑的用户端连上 B 电脑的管理端，两台机器必须能互相「喊到」：

- 连 **同一个 Wi-Fi**，或
- 插在 **同一间机房/同一个交换机** 的网线

手机开热点也可以，但双方都要连这个热点。  
一边连宿舍 Wi-Fi、一边连手机流量，**一定连不上**。

在用户端那台 Ubuntu 终端里测（把 IP 换成服务器底栏上的）：

```bash
ping 192.168.1.8
```

能通再开用户端。一直失败：Wi-Fi 不同，或虚拟机网络模式不对（见下）。

### 虚拟机网络：桥接 vs NAT（VMware）

管理端如果跑在虚拟机里，虚拟机也有自己的 IP。

| 模式 | 像什么 | 组员能不能连 |
|------|--------|----------------|
| **NAT**（默认常见） | 住酒店：对外只看到宿主机，虚拟机是内部分机 | **只有这台 Windows 自己** 较容易访问；旁边同学的电脑通常进不去 |
| **桥接 Bridged** | 虚拟机直接在 Wi-Fi 上有自己的门牌 | **同一 Wi-Fi 的同学可以连** |

联调时请把 **当服务器的那台虚拟机** 改成桥接：

1. 虚拟机关机或先改网卡再开
2. VMware：虚拟机 → 设置 → 网络适配器 → **桥接模式（Bridged）**（勾选「复制物理网络连接状态」更好）
3. 重新打开管理端，看窗口 **最底下** 的新 IP，以这一行为准
4. 把新的 `IP:8888` 发给组员

NAT 下的地址经常是 `192.168.122.x` 或 `192.168.88.x`，那是虚拟机内部网，**不要** 发给旁边物理机上的同学当服务器地址。

### 防火墙

服务器那台 Ubuntu 若开了防火墙，需要放行两个端口：

```bash
sudo ufw allow 8888
sudo ufw allow 5000
sudo ufw reload
```

没开 ufw 可以不管。

## 4. 一台当服务器、其他人当用户端

日常改功能、自己点一遍：请用 **第 2 节**，不要走本节。

本节只用于全组测 **同一份数据**（同一批用户、同一批订单）。

### 角色怎么分

| 角色 | 几台 | 虚拟机里开什么 | 不要开什么 |
|------|------|----------------|------------|
| **服务器电脑**（事先说好谁当） | **只能 1 台** | 管理端 + 可选大屏 | 不要再在别人电脑上开第二份管理端 |
| **测试电脑**（其余所有人） | 可以很多台 | **只开用户端** | **不要开管理端** |
| 任何人想「看运营数据」 | — | 浏览器打开 `http://服务器IP:5000` | 这不是管理端，改不了用户冻结、加电站 |

队友 **可以** 在自己虚拟机里编译出管理端，也可以在 **单人自测** 时打开它（第 2 节）。  
但是 **一旦开始组内联调**，其他人虚拟机里的管理端必须关掉，只留服务器那一台。

想操作「冻结用户、加电站、重启桩」：请到 **服务器那台** 电脑前操作，或让服务器同学开共享屏幕 / Ubuntu 远程桌面。  
管理端没有「远程登录另一台管理端」的功能，因为管理端本身就是服务器。

### 服务器同学操作

1. 虚拟机网络改成 **桥接**（第 3 节）。
2. 只开管理端：

```bash
cd ~/ChargeHub-Linux/admin && ./run.sh
```

登录 `admin` / `123456`。

3. 看窗口 **最底部状态栏**，类似：

```text
用户端请填写  192.168.1.8:8888    数据库 /home/bit/ChargeHub-Linux/admin/data/chargehub.db
```

把 `192.168.1.8:8888` 发到群里（以你屏幕上的为准）。

4. 建议同时开大屏（方便别人只看不改）：

```bash
cd ~/ChargeHub-Linux/dashboard
CHARGEHUB_DB=$HOME/ChargeHub-Linux/admin/data/chargehub.db python3 app.py
```

群里同步：大屏地址 `http://192.168.1.8:5000`。

5. **联调期间不要关管理端窗口。**

### 其他同学操作（用户端）

1. 自己虚拟机里 **不要** 再双击 `admin/run.sh`。若已经开了，关掉。
2. 打开用户端（自己编的或拷服务器的 `ChargeHub-Linux/user` 整夹都可以）：

```bash
cd ~/ChargeHub-Linux/user && ./run.sh
```

3. 「服务器地址」**粘贴群里那串**，例如 `192.168.1.8:8888`，不要用 `127.0.0.1:8888`。
4. 点「连接」，成功后再登录。可以注册自己的手机号，也可以商量着用演示号（演示号不要注销）。
5. 充电、预约产生的订单，会出现在 **服务器那台** 的管理端和 `http://服务器IP:5000` 大屏上。

### 联调检查清单

- [ ] 全组只开着 **一份** 管理端
- [ ] 服务器虚拟机是 **桥接**
- [ ] 大家连 **同一个 Wi-Fi**
- [ ] 用户端地址与管理端底栏 **完全一致**（含 `:8888`）
- [ ] `ping 服务器IP` 能通
- [ ] 管理端窗口没关

## 5. 多管理端冲突：为什么、怎么处理

### 原因（必须理解）

本项目里：**管理端 = 服务器**。它同时做三件事：

1. 打开并 **独占写入** `data/chargehub.db`
2. 在 **8888** 端口等待用户端
3. 显示运营窗口

所以：

| 错误做法 | 实际后果 |
|----------|----------|
| 同一台 Ubuntu 开两个管理端 | 第二份会被文件锁拦住，或提示 8888 被占用 |
| **两台电脑各开一个管理端** | 两套库、两个 8888。用户端连谁，数据就在谁那里。看起来都能登录，但订单对不上、余额对不上 |
| 把 `.db` 放到共享盘让两台一起写 | SQLite 不能当网上的共享数据库用，会损坏或锁死 |
| 联调时自己又开了管理端，用户端仍填 `127.0.0.1` | 你在测自己的空库，不是组里的服务器 |

程序 **不会** 自动把两台管理端的数据合并。

### 规定（联调期间）

1. 群里指定 **一名「值班服务器」**，只他的虚拟机开管理端。
2. 其他人虚拟机：**只开用户端**，地址填值班机器底栏 IP。
3. 需要看后台：用浏览器开大屏；需要改后台：让值班同学操作或坐到那台电脑前。
4. 换人当服务器：先 **完全退出** 旧管理端，再在新电脑上开管理端。注意：新电脑是 **空库或自己的旧库**，不会自动带着上一台的订单走。要延续同一份数据，请继续用原来那台，或拷贝 `ChargeHub-Linux/admin/data/chargehub.db`（必须在管理端 **已关闭** 后拷）。

### 单人开发时可以开自己的管理端

改界面、改业务时，每个人在自己虚拟机开管理端 + 用户端（第 2 节）完全没问题，那是各测各的。  
**不要把「自己的管理端」和「值班服务器」混在一次联调里。**

## 6. 模块划分与接口

```
用户端 userclient          管理端 adminserver                 大屏 / 预测
┌─────────────┐  TCP:8888  ┌──────────────────────┐ 只读db  ┌──────────┐
│ UserWindow  │ ─────────► │ TcpServer            │ ◄───── │dashboard │
│ Client      │  JSON帧    │ Dispatch  → Database │        │ ml/      │
└─────────────┘            │ MainWindow（同进程）  │        └──────────┘
                           └──────────────────────┘
```

源码目录对应关系：

| 目录 / 文件 | 职责 | 对外接口 | 协作时改哪里 |
|-------------|------|----------|--------------|
| `common/protocol.*` | 4 字节长度 + JSON 拆包组包 | `Protocol::pack` / `append` / `nextPacket` | 改帧格式必须用户端、管理端一起改 |
| `userclient/src/client.*` | TCP 客户端 | `connectTo(ip,8888)` `request(type,data,token)` | 只加请求，禁止 `QSqlDatabase` |
| `userclient/src/userwindow.*` | 用户界面 | 按钮 → `Client::request` | 界面与交互 |
| `adminserver/src/tcpserver.*` | 听 8888、多用户连接；断线 60s 释放桩 | 内部调用 `Dispatch::handle` / `releaseStaleSession` | 会话与超时 |
| `adminserver/src/dispatch.*` | 装配与兼容门面 | `handle`（用户端）；`adminLogin` / `freezeUser` 等（GUI） | 对外签名不要改 |
| `adminserver/src/services/` | 会话 / 充电 / 预约 / 电站 / 用户 / 评价 / 运营 / 分析 | 各领域函数；找桩 GPS 在 `StationService` | 加业务优先改对应服务 |
| `adminserver/src/transport/` | 路由、鉴权、幂等 | `RequestDispatcher` | 新 type 在 `registerRoutes` 注册 |
| `adminserver/src/database.*` | SQLite 唯一写入口 | `query` / `one` / `execute` / `transaction` | 改表要同步 `schema.sql` |
| `adminserver/src/mainwindow.*` | 运营界面 | 直接调 Dispatch，不走 Socket | 后台页面 |
| `adminserver/src/chartwidget.*` | 自绘图表 | `setPoints` / `setBars` / `setSlices` | 仅显示 |
| `dashboard/app.py` | Flask 只读大屏 | `GET /` `GET /api/overview` `GET /api/analysis` | 图表页；禁止 UPDATE 订单 |
| `ml/forecast.py` | 负荷预测 | 写 `load_forecast` 等分析表 | 不改余额、不改桩状态 |
| `database/schema.sql` | 表结构说明 | 与 C++ 建表一致 | 改库先改此文件再改 C++ |
| `protocol/messages.md` | 报文 type 列表 | 联调对照表 | 新增 type 必须更新此文件 |

用户端报文的 type、字段、错误码见 **`protocol/messages.md`**。新增接口的步骤：

1. 在 `messages.md` 加一行 type
2. 在对应 `services/` 里实现，并在 `Dispatch::registerRoutes` 注册
3. 在 `UserWindow` 里 `request(...)` 并处理 `responded`

管理端 GUI 新增按钮：只调 `Dispatch` 的 C++ 方法，不要再发明一套 Socket。

## 7. 数据库设计

**文件位置（运行时）：** 服务器电脑  
`~/ChargeHub-Linux/admin/data/chargehub.db`

**谁能写：** 只有 `adminserver`。用户端不准打开该文件。大屏只读。

**设计分层：**

1. **账号层** `admin` 运营账号；`user` 车主（余额、状态：正常/冻结/注销）。注销只改状态留档，不删行。
2. **资料层** `user_avatar` 头像二进制（与 user 一对一）。
3. **资源层** `station` 电站；`pile` 电桩（闲置/在用/故障）。站 1 对多 桩。
4. **交易层** `charge_order` 订单；`recharge_log` 充值；`reservation` 预约。
5. **评价层** `station_review` / `review_doc`。
6. **审计层** `audit_log`。
7. **分析层** `load_forecast` `hourly_load` `fault_risk` `analysis_alert` `dispatch_plan` `analysis_report`（预测与大屏用，不参与扣费）。

关系简图：

```
admin
user ─── user_avatar
user ─── charge_order ─── pile ─── station
user ─── reservation  ─── pile
user ─── recharge_log
user ─── station_review ─── station / pile
```

字段级说明以 **`database/schema.sql`** 为准（含 CHECK、外键、索引）。  
C++ 启动时 `CREATE IF NOT EXISTS` 并给旧库补列，不以删除用户数据的方式「升级」。

联调时这份库只存在于 **值班服务器** 那台机器。别人电脑上的 `chargehub.db` 是另一份，互不影响。

## 8. 改代码与协作约定

改完源码后在 Ubuntu 执行：

```bash
bash /mnt/hgfs/ChargeHub/scripts/rebuild.sh
```

不要在共享盘上直接 `make`。

| 类别 | 规则 | 例子 |
|------|------|------|

| JSON | 小驼峰 | `pileId` `radiusKm` |

各模块文件头注释（`@file` / `@brief`）已写在对应 `.h` / `.cpp`，协作时先读文件头再改。

## 9. 打不开时

| 现象 | 先做什么 |
|------|----------|
| 用户端连不上（本机自测） | 管理端开了吗？地址是不是 `127.0.0.1:8888`？ |
| 用户端连不上（连组里服务器） | 别人是不是也开了管理端？你填的是不是 `127.0.0.1`？Wi-Fi 是否相同？虚拟机是否桥接？`ping` 通不通？ |
| 提示已有管理端 / 8888 占用 | 关掉多余的管理端，全组只留一份 |
| 能登录但订单和别人不一样 | 你们连的不是同一台服务器（两套库） |
| 浏览器打不开大屏 | 服务器上要跑 `python3 app.py`；别人请用 `http://服务器IP:5000` 不要用 127.0.0.1 |
| 双击 `run.sh` 没反应 | 还没编过，回到第 1 节 |
| 改代码没变化 | 必须再跑 `rebuild.sh` |
