## 1. HDFS 与 Hadoop

整块职责：单节点 Hadoop 的配置、启动 NameNode/DataNode、把 CSV 上传到 HDFS、给机器学习一个 `hdfs://` 地址。  
不管：扩样噪声、GBT/KMeans、Vue 页签、清洗漏斗口径。  
交付：`hdfs://localhost:9000/chargehub/dataset/sessions.csv` 可读；NameNode 挂了时对方知道会走 `file://`。

这是一台 WSL 上的 Hadoop 接口，不是多机 YARN 集群。

| 文件路径 | 文件含义 | 你的具体职责 |
|----------|----------|--------------|
| `bigdata/conf/core-site.xml` | Hadoop 核心配置，决定默认文件系统是谁 | 讲清 `fs.defaultFS = hdfs://localhost:9000`：本机 NameNode 端口 9000 |
| `bigdata/conf/hdfs-site.xml` | HDFS 副本数和磁盘目录 | 讲清 `dfs.replication=1`（单节点只有一块盘）；`dfs.namenode.name.dir` / `dfs.datanode.data.dir` 是元数据和块存放位置 |
| `bigdata/conf/spark-defaults.conf` | Spark 默认参数（和 Hadoop 共用这一份） | **只讲** `spark.hadoop.fs.defaultFS`：让 Spark 去连上面那个 NameNode。`spark.master`、内存归机器学习 |
| `bigdata/paths.py` | 全模块统一找数据路径的 Python 文件 | **只讲** `hdfs_uri`、`input_uri`：环境变量 `CHARGEHUB_HDFS`，默认 `hdfs://localhost:9000`，数据集拼成 `/chargehub/dataset`。本地 CSV 目录归机器学习 |
| `bigdata/spark_analyze.py` | Spark 挖掘主程序（大部分归机器学习） | **只讲** `_try_hdfs_ls`、`resolve_input`：用 Hadoop FileSystem API 探测 `sessions.csv` 在不在 HDFS；没有则改读 `file://dataset/big`。大屏 KPI 的 `engine`（HDFS / LOCAL）来自这里 |
| `bigdata/scripts/setup_hadoop_spark.sh` | 在 WSL 一次性安装 JDK / Hadoop / Spark | **只讲** OpenJDK 11 与 Hadoop 3.3.6 安装段。Spark 安装段给机器学习看一眼即可 |
| `bigdata/scripts/start_hdfs.sh` | 启动单节点 HDFS | 整文件都是你的：调用 `start-dfs.sh` 起 NameNode + DataNode。答辩可讲 `jps` 里应看到这两个进程 |
| `bigdata/scripts/ingest_hdfs.sh` | 把本地 CSV 上传进 HDFS | 整文件都是你的：`hdfs dfs -mkdir` + `-put`，源目录 `dataset/big`，目标 `/chargehub/dataset` |
| `bigdata/scripts/run_pipeline.sh` | 一键流水线（扩样 → HDFS → spark-submit → enrich） | **只讲** 里面调用 `start_hdfs` / `ingest` 的两步。`spark-submit` 和 enrich 归机器学习 |
| `bigdata/README.md` | 大数据模块操作说明 | 讲步骤 1、3：装环境、起 HDFS、上传。步骤 4 spark-submit 不是你的 |
| `dataset/big/` | 扩样后的 CSV 目录 | 只作为 **put 的源目录**。文件是怎么扩出来的问机器学习；你保证上传成功 |

## 2. 机器学习分析

整块职责：扩样、Spark 作业、回归/聚类/RFM/异常/电池分、把结果写成 JSON 和分析表。  
不管：怎么配 core-site、怎么 `start-dfs`、页签 CSS、GBK 怎么读。  
交付：`spark_report.json` 的模型键；管理端 `analysis_*` 表里有预测/风险。

| 文件路径 | 文件含义 | 你的具体职责 |
|----------|----------|--------------|
| `bigdata/expand_dataset.py` | 把约 3.4k 真实会话按站/时段加噪声扩到约 22 万行 | 整文件：`expand_sessions`、`expand_battery`、`jitter`、`main`。写出 `dataset/big/`，不写业务库。Hadoop 同学再 put 到 HDFS |
| `bigdata/paths.py` | 统一找数据路径 | **只讲** `raw_dir`、`big_dir`、`out_dir`、`report_path`：本地 CSV 和 `spark_report.json` 落盘位置。`hdfs_uri` 归 Hadoop |
| `bigdata/spark_analyze.py` | Spark 挖掘主程序：建会话、跑全部模型、写总 JSON | `_spark`（默认 `local[*]`）、`write_json`、`main`；以及全部模型函数：`train_models`（GBT/RF/线性回归预测单次 kWh，80/20，MAE/RMSE/R²）、`hourly_and_forecast`（1/6/24h 负荷）、`cluster_stations` + `name_station_clusters`（KMeans k=4 + PCA，相对命名）、`user_rfm`、`peak_classifier`、`isolation_anomalies`、`assoc_rules`、`battery_risks`、`weekday_hour` / `platform_mix` / `station_rank`、`build_alerts`。读哪条 URI 问 Hadoop 的 `resolve_input` |
| `bigdata/enrich_dashboard.py` | 扫 CSV，打成大屏用的扁平 JSON | `scan_sessions`、`scan_stations`、`scan_soc`、`build_daily_series`、`forecast_7`、`build`、`main`（日趋势、分箱、7 日基线）；`rfm_pack` / `rank01`（高价值/流失评分，人数可以不等）；`metrics` / `kmeans` / `silhouette` / `station_k_curve`（纯 Python 误差与 K 曲线）。`scan_quality`、`fix_year`、`read_csv_rows` 归清洗 |

| `bigdata/conf/spark-defaults.conf` | Spark 默认参数 | **只讲** `spark.master`、`spark.driver.memory`、`shuffle.partitions`（单机多核）。`fs.defaultFS` 那一行归 Hadoop |
| `dataset/big/sessions.csv` | 扩样后的充电会话（Spark 主输入） | 讲表头字段；训练读它。是否已在 HDFS 上问 Hadoop |
| `dataset/big/stations.csv` | 扩样后的电站维表 | 聚类 join 站名用 |

交付：各 Screen 收到的 `*Opt` props。前端只摆格子、不改 series。

| 文件路径 | 文件含义 | 你的具体职责 |
|----------|----------|--------------|

## 5. 数据清洗

整块职责：按《数据清洗需求表》定义脏数据并统计，给质量页数字。  
不管：扩样、ECharts option、Spark 聚类。  
交付：合格字段约定（电量>0、时长 0–24h、年份可修）；`charts.quality` 给可视化画漏斗。

| 文件路径 | 文件含义 | 你的具体职责 |
|----------|----------|--------------|
| `dataset/数据清洗需求表.xlsx` | 老师给的清洗规则表，口径源头 | 每一行规则都要对上代码里的异常名。答辩以这张表为准 |
| `dataset/04.数据集最终版/nvv2t.csv` | 真实充电会话（约 3.4k） | 清洗**只扫这张原始表**，不扫扩样 `dataset/big/`。关键列：`created`、`kwhTotal`、`chargeTimeHrs`、`charging_fees` |
| `dataset/04.数据集最终版/nvv2t_md_end.csv` | 原始电站维表 | 站名、地址、设备数；质量页可对照站数字段 |
| `dataset/04.数据集最终版/dsv13r2.csv`（或 `dataset/dsv13r2.csv`） | 原始电池包遥测 | 编码常为 **GBK**。`pack_voltage`>0 算有效记录 |
| `bigdata/enrich_dashboard.py` | 扫表并写出 `dash_charts.json`（大部分归机器学习） | **只讲** `read_csv_rows`（依次试 utf-8 / gbk / gb18030）、`fix_year`（`0025-` → `2025-`）、`scan_quality`（年份异常、电量≤0、时长越界、免费单、付费单、漏斗、电池通过率）、`fee_bucket` 里「免费」（≤0.01 元）。`build` / `rfm_pack` 归机器学习 |
| `bigdata/output/dash_charts.json` | 大屏扁平 JSON | **只讲** 键 `quality`：`issues`、`funnel`、`pass_rate`、`battery_valid_rate`、`free_orders`、`paid_orders`。可视化只负责画，口径由你解释 |
| `dashboard/web/src/screens/QualityScreen.vue` | 质量页 | 讲每个图/数字对应哪条清洗规则。格子怎么排归前端 |

漏斗口径（你要能背）：原始会话 → 电量>0 → 时长 0–24h → 付费单。免费单按表要求单列统计，不是直接当脏数据删掉。

## 7. 怎么用这五张表

1. 每人只打印自己那一张，按「文件路径」在 IDE 里打开，对照「具体职责」把 docstring 过一遍。  
2. 老师指到别人的文件：说「那是某某表里的文件，我只认某某契约」。契约见答辩说明第 7–8 节。  
3. 共用文件：`spark_analyze.py`、`enrich_dashboard.py`、`paths.py`、`spark-defaults.conf`、`dash_charts.json`、`useDashboard.js`、各 `screens/*.vue`。务必看清「你的具体职责」列。
