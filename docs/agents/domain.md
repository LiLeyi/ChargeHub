# Domain Docs

本仓库使用 **single-context** 领域文档布局。

## 探索代码前

- 如果根目录存在 `CONTEXT.md`，先阅读它。
- 阅读 `docs/adr/` 中与当前模块有关的架构决策记录。
- 文件或目录尚不存在时静默继续，不提前创建空文档。
- `CONTEXT.md` 与 ADR 由领域建模流程在术语或决定真正明确后按需创建。

## 使用领域语言

Issue 标题、重构方案、诊断假设和测试名称应采用 `CONTEXT.md` 中已经定义的术语，避免改用含义不一致的近义词。

如果需要的概念尚未记录，应先判断是否误用了项目术语；确认是缺口后，再交由领域建模流程补充。

## 处理 ADR 冲突

如果拟议方案与已有 ADR 冲突，必须明确指出冲突，不得静默覆盖既有决定。
