# ChargeHub 概要设计说明书

## 1. 系统目标

东软电动汽车充电桩应用管理平台覆盖「用户端—服务端—数据端—决策端」。车主找桩、充电、结算；运营人员管站管桩管用户并看营收；决策大屏只读展示；负荷预测只写分析表。

模块怎么协作、一次开充怎么走，见 `docs/模块与协作说明.md`（答辩主讲稿）。

## 2. 逻辑架构

```
表示层   用户端 Qt（桌面）     管理端 Qt（宽屏）     Web 大屏 ECharts
通信层   QTcpSocket / 长度前缀JSON    同进程调用          HTTP 只读
业务层   （无）                     Dispatch 唯一规则
数据层   （无）                     SQLite WAL
```

约束：用户端禁止连接 SQLite；大屏与机器学习禁止改余额、改桩状态、改订单。

## 3. 进程

| 进程 | 职责 |
|------|------|
| adminserver | GUI + 监听线程 + 每连接一 Worker + SQLite 唯一写入 |
| userclient | 仅 Socket 客户端，不打开数据库 |
| dashboard | Flask + ECharts 只读大屏 |
| ml/forecast.py | 离线预测，失败回退小时均值 |

## 4. 核心状态机

电桩：闲置 → 在用 → 闲置；故障可由运营标记，远程重启回到闲置。  
订单：充电中 → 待结算 → 已完成。同一用户同时最多一条未完成订单（库层部分唯一索引）。  
用户端全部 TCP 断开且 60 秒未重连：充电中订单自动收成待结算，桩回闲置。

计费：`kWh = 功率kW × 时长h`，有 `tariff_rule` 时按小时分段计价，否则用站基准价。费用按分取整后再写库。开充 / 停充 / 结算 / 充值同一事务提交。Token 落 `session` 表。充电中可推送 `PUSH_CHARGE`（旧客户端可忽略）。

## 5. 安全

管理员密码 SHA256；登录失败统一「账号或密码错误」；用户/管理员接口隔离；关键写操作记 audit_log。

## 6. 部署

开发机可用 Python/PyQt 运行；课程提交用 Qt Creator 打开 `ChargeHub.pro` 在 Ubuntu 22.04 编译。数据库文件 `database/chargehub.db`。
