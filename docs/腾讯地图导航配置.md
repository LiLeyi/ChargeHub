# 腾讯位置服务（地图 / 天气 / 地址）

用户端和管理端共用同一套腾讯 WebService，凭证只放本机，不要提交。

## 已经接上的接口

| 能力 | 谁用 | 接口 | 失败时 |
|------|------|------|--------|
| 静态地图 | 用户端「位置 / 导航」 | `/ws/staticmap/v2/` | 仍可打开腾讯地图网页 |
| 路线规划 | 用户端查询驾车/步行/骑行/公交 | `/ws/direction/v1/*` | 只改提示，不影响订单 |
| 实况天气 | 用户端地图弹窗；管理端「刷新预测」 | `/ws/weather/v1/` | 预测回退到模拟天气 |
| 地址解析 | 找站关键词本地对不上时 | `/ws/geocoder/v1/` | 仍按海淀中关村一带检索 |

找站会先匹配电站名和本地地标（北理工、五道口等），对不上才问腾讯。订单、余额、Socket 字段都不经过这些 HTTP。

## 本机配置

1. 打开 [腾讯位置服务控制台](https://lbs.qq.com/dev/console/application/mine)，给这个 Key **勾选并分配额度**：
   - WebService API
   - 静态图
   - 路线规划（驾车 / 步行 / 骑行 / 公交）
   - 天气查询
   - 地址解析（正地理编码）
2. 复制 `common/tencent_credentials.h.example` 为 `common/tencent_credentials.h`，填入 Key；若控制台开了签名校验，再填 SK。
3. 也可以用环境变量覆盖，不改文件：

```powershell
$env:CHARGEHUB_TENCENT_MAP_KEY = "你的Key"
$env:CHARGEHUB_TENCENT_MAP_SK = "你的SK"
```

Linux：

```bash
export CHARGEHUB_TENCENT_MAP_KEY='你的Key'
export CHARGEHUB_TENCENT_MAP_SK='你的SK'
```

改完 Key 后重新 `bash scripts/rebuild.sh`，再开用户端 / 运营后台。

`tencent_credentials.h` 和 SK 不要提交到 Git。

## 怎么试

1. 用户端登录 → 找站 → 打开某站「位置 / 导航」：应看到天气；静态图若提示配额用尽，点「打开腾讯地图」仍可导航。
2. 运营后台登录后刷新预测：天气因子应显示实况（例如「晴 26℃ · 海淀区」），不是按日期轮换的模拟值。
3. 找站输入控制台能解析的地址（本地地标对不上时）会落到腾讯返回的坐标。

静态图报「当日调用量已达上限」（status 121）时：到控制台给静态图加配额，或换 Key 写进 `common/tencent_credentials.h`。天气和地址不受静态图额度影响。
